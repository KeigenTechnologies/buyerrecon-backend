## 2. Purpose

Define **exact read-only operator commands** that a future Gate 4A execution PR could run, after explicit Helen GO, to establish production-readiness audit / preflight evidence before any Gate 4B artifact/config bundle work or any Gate 4C canary activation.

Gate 4A should answer, by category only:

- What is the current website / ThinSDK / `endpointUrl` state on `buyerrecon.com`?
- Is production still pointed at the Render legacy `/collect` endpoint, at a Sprint 2 `/v1/event` target, at an absent endpoint, or at an unknown target?
- Are `/var/www` artifacts known, hashable, and matched to an approved source-of-truth record?
- Is rollback/backup posture known? Does a recorded one-step revert path exist?
- Are production DB roles and grants in the expected migration-016 state?
- Are Lane A/B grant-safety invariants still intact (no writer roles hold `SELECT`/`INSERT`/`UPDATE`/`DELETE`)?
- Is there any unexpected Sprint 2 production traffic?
- Are any stop-lines triggered that would forbid Gate 4B / Gate 4C from proceeding?

Gate 4A does **not** answer:

- whether the SDK body shape is compatible (Gate 1 territory),
- whether the production runtime role can execute the actual SQL path (Gate 3 territory),
- whether the production collector can accept a controlled event (Gate 4C territory),
- whether organic Sprint 2 traffic is healthy (Gate 4D territory),
- whether Pass 1 / Trust / Pass 2 / Lane A/B output is safe to emit (separate governance chain).

A Gate 4A PASS means only that the read-only audit found the current posture acceptable for the **next separately gated planning or preflight step**. It does not unlock Gate 4B, Gate 4C, Gate 4D, Gate 4E, or production cutover.

## 3. Operator prerequisites

Before any future Gate 4A execution PR runs any command in this runbook, the operator must confirm all of:

- Explicit Helen GO is recorded, scoped to that specific Gate 4A execution PR.
- A single operator shell is in use. No parallel shells. No long-running automation.
- `set +x` is active (no command-echo).
- `unset HISTFILE` has been run (no shell-history capture of session commands).
- `umask 077` is active (any incidental file created during the audit is operator-only).
- The host is the explicitly-named production host category for the audit, confirmed before any `cd`, `git`, `ls`, `grep`, or `psql` runs against production paths or DSNs.
- All commands are read-only. No `rm`, no `mv`, no `cp` of `/var/www`, no `chown`, no `chmod` of production paths, no `systemctl restart`, no `nginx -s reload`, no `psql`-mutating statements.
- Categorical outputs only. No raw secret, no raw payload, no raw customer data, no raw identifier is recorded.
- A scratch report file path is decided in advance, outside any web-served directory, with `umask 077`. This file holds only categorical lines and is cleaned up in §5.J.

If any prerequisite cannot be satisfied, **stop** and do not proceed to §5.

## 4. Secret-safety rules

A future Gate 4A execution PR must **never** print, paste, copy, commit, screenshot, or record:

- a production token value (raw, prefix, suffix, or length),
- a `token_hash` value,
- a `token_id` value,
- `SITE_WRITE_TOKEN_PEPPER` or any pepper material,
- `DATABASE_URL` / `STAGING_DATABASE_URL` / any DSN / any connection string,
- an `Authorization:` header,
- a `Bearer ` prefix,
- a `request_id` UUID,
- a `session_id` value,
- a raw event payload (body, JSON, blob),
- a raw HTTP response body,
- a full URL query string containing identifiers,
- customer data of any kind,
- `BEGIN PRIVATE KEY` / `BEGIN CERTIFICATE` material,
- a raw `env` dump,
- vault content,
- shell history,
- raw log lines containing identifiers.

A future Gate 4A execution PR **may** record categorical evidence:

- file-exists yes/no,
- sha256 hash of a static, publicly-served artifact file (no secret-bearing files),
- `endpointUrl` category (`render_legacy_collect` / `sprint2_v1_event` / `absent` / `unknown`),
- DB/table/role/grant category yes/no,
- count-only DB outputs,
- HTTP status class for a safe health endpoint (if and only if Gate 4A approves that health endpoint as safe),
- rollback file exists yes/no,
- cleanup yes/no.

If any output would risk crossing this boundary, **stop** and record `BLOCKED_SECRET_SURFACE` instead of forcing the check through.

### I. Stop-line evaluation

After §5.A–§5.H complete, the audit operator records a categorical pass/fail line for each stop-line surface. Any single triggered stop-line forces an overall `BLOCKED` verdict in §6.

- `endpointUrl_unexpected`: true if §5.D category is `unknown`, or `sprint2_v1_event` without a recorded Gate 4C approval.
- `var_www_unknown_drift`: true if §5.C found an artifact whose sha256 does not match any approved source record, or a file is missing that should be present.
- `rollback_missing`: true if §5.E found backup directory missing, backup artifact missing, or rollback runbook doc missing.
- `production_db_grant_drift`: true if any §5.F Lane grant boolean does not match expected.
- `lane_rows_unexpected`: true if §5.F Lane A/B count is non-zero.
- `lane_writer_activity_observed`: true if §5.F or §5.G shows evidence of Lane A/B write activity without authorisation.
- `customer_output_found`: true if any artifact, route, or surface inspected reveals customer-facing output (Pass 1 / Trust / Pass 2 / Lane report / dashboard) being emitted.
